# 🧠 Quiz: Защита Проекта 3 (AI-Driven BI Pipeline)

---

### Вопрос 1
Какова ключевая ценность связки LLM API + Векторная БД (RAG) в аналитическом пайплайне компании?
- [ ] Полная замена живых сотрудников на роботов.
- [x] Возможность автоматически структурировать до 80% закрытых корпоративных данных (отзывы, регламенты, документация) и открывать к ним мгновенный семантический доступ на естественном языке без галлюцинаций.
- [ ] Увеличение расхода памяти на сервере.
*Объяснение*: RAG объединяет вычислительную мощь LLM с актуальными закрытыми данными компании.

### Вопрос 2
Что обеспечивает надежную защиту от галлюцинаций в корпоративном Text-to-SQL ассистенте?
- [x] Ограничение генерации SQL к реальной DDL схеме БД, проверка через EXPLAIN/AST и запрет деструктивных операций (DROP/DELETE).
- [ ] Отключение интернета.
- [ ] Использование исключительно коротких вопросов от пользователей.
*Объяснение*: Верификация схемы и AST-валидация гарантируют надежность получаемых цифр до передачи данных в BI.

### Вопрос 3
Зачем при построении RAG-ассистента над метаданными хранилища использовать гибридный поиск (Keyword + Semantic Vector Search)?
- [ ] Векторный поиск не умеет работать со строками.
- [x] Векторный поиск находит контекстный смысл («выручка компании»), а ключевой поиск точно матчит технические идентификаторы колонок (`fct_mrr_v2`).
- [ ] Это снижает объем оперативной памяти в 10 раз.
*Объяснение*: Гибридный поиск дает наивысшую точность (Recall@K) при поиске по техническим схемам баз данных.

### Вопрос 4
Какой механизм позволяет подавать на вход LLM API миллионы клиентских обращений без риска перерасхода бюджета компании?
- [ ] Ручной ввод текстов в веб-интерфейс чат-бота.
- [x] Использование асинхронного Batch API со скидкой 50% и Prompt Caching для системных инструкций.
- [ ] Отказ от парсинга текста.
*Объяснение*: Batch API и кэширование префиксов — ключевые инструменты FinOps для больших корпусов данных.

### Вопрос 5
Что такое Self-Correction Loop в агентных аналитических системах?
- [ ] Автоматическое удаление неверных строк из исходной базы данных.
- [x] Механизм, при котором агент перехватывает ошибку выполнения SQL-запроса, анализирует текст ошибки и автоматически генерирует исправленный запрос.
- [ ] Перезагрузка виртуальной машины при сбое скрипта.
*Объяснение*: ReAct цикл с самокоррекцией позволяет агенту устранять синтаксические опечатки без участия человека.
