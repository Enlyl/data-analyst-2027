# 🧠 Quiz: Самопроверка по Модулю 2 (SQL)

### Вопрос 1
В чем разница между `RANK()` и `DENSE_RANK()`?
- [ ] Разницы нет
- [x] При одинаковых значениях RANK оставляет пропуски в нумерации (1, 2, 2, 4), а DENSE_RANK нумерует без пробелов (1, 2, 2, 3)
- [ ] DENSE_RANK работает только в PostgreSQL

### Вопрос 2
Зачем нужна конструкция `WITH` (CTE)?
- [ ] Она ускоряет любой запрос в 100 раз
- [x] Она позволяет разбить сложный запрос на логические читаемые блоки и использовать их повторно
- [ ] Без нее нельзя соединять таблицы

### Вопрос 3
Какой результат вернет `COUNT(*)` vs `COUNT(column_name)` если в колонке есть NULL?
- [ ] Одинаковый
- [x] `COUNT(*)` считает все строки, а `COUNT(column_name)` игнорирует строки с NULL
- [ ] Вернет ошибку базы данных

### Вопрос 4
В чем ключевое отличие оконной функции DENSE_RANK() от RANK()?
- [ ] DENSE_RANK работает только в PostgreSQL.
- [x] DENSE_RANK не оставляет пропусков в нумерации рангов при наличии одинаковых значений (например: 1, 2, 2, 3 вместо 1, 2, 2, 4 у RANK).
- [ ] RANK нумерует строки в обратном порядке.
*Объяснение*: DENSE_RANK плотно нумерует ранги без скачков при дубликатах.

---

### Вопрос 5
Почему CTE (Common Table Expressions, блок WITH) предпочтительнее глубоко вложенных подзапросов в SELECT?
- [ ] CTE всегда выполняется быстрее оптимизатором.
- [x] CTE делает код модульным, легко читаемым человеком и AI, упрощает дебаг и повторное переиспользование промежуточных выборок.
- [ ] Вложенные подзапросы запрещены в стандарте SQL 2026.
*Объяснение*: Чистота и поддерживаемость кода снижают количество ошибок при передаче запросов между аналитиками.
